# Climbing Activity App

クライミングの記録とキャラクター育成を組み合わせた、スマートフォン向けアクティビティアプリ構想です。

単なる登攀ログではなく、**現実のクライミング活動そのものがゲーム内キャラクター／モンスターの成長につながる**ことを中心コンセプトとします。

## コンセプト

基本ループは以下です。

1. クライミングをする
2. 登った課題を短時間で記録する
3. グレード・完登・トライ数・課題特性などから成長値を算出する
4. モンスター／キャラクターが成長する
5. 休養日には回復・適応が進む
6. また登りたくなる

重要なのは、記録作業そのものを目的にせず、**「登った結果を数秒で入力すると、ゲーム内で反応が返ってくる」**体験にすることです。

## 最優先UX

### クイック入力

1課題あたり数秒で入力できることを優先します。

必須候補：

- グレード
- ボルダー / リード
- 完登 / 未完登
- トライ数
- 一撃・Flash等の実績
- 傾斜
- 課題特性：Physical / Balance / Technical

日付・時刻・ジムなど、セッション単位で共通化できる情報は毎回入力させません。

### 課題特性入力

Physical / Balance / Technical の3項目を横並びで表示し、バーをタップまたはスワイプして直感的に自己申告できるUIを想定します。

例：

- Physical: 4 / 5
- Balance: 2 / 5
- Technical: 3 / 5

厳密な採点ではなく、ユーザーが「この課題はこんな感じだった」と数秒で記録できることを優先します。

### 傾斜

Physical / Balance / Technical とは別軸にします。

候補：

- Slab
- Vertical
- Slight Overhang
- Overhang
- Steep / Roof

傾斜はアイコンまたは5段階選択にして、細かな角度入力は要求しません。

## 育成システム

登攀ログからキャラクターの成長傾向を算出します。

例：

- Physical課題を多く登る → Power系能力が伸びる
- Balance課題を多く登る → Balance系能力が伸びる
- Technical課題を多く登る → Technique系能力が伸びる
- 高難度課題の完登 → 大きな経験値
- Flash / 一撃 → ボーナス
- 多数のトライ後に完登 → Persistence系の成長や特別演出
- リード → Endurance系への寄与
- 強傾斜 → Power / Core系への寄与

単純な最高グレードだけで決めず、クライマーごとの登り方がキャラクターに反映される設計を目指します。

## 休養日の扱い

休養はクライミング上重要なので、連続活動だけを報酬化しません。

- クライミングをしなかった日は原則として自動的にRest Dayとして扱う
- Rest Dayではキャラクターが回復する
- 直前のトレーニング成果が定着する演出を入れる
- 適切な休養でも育成が進むようにする

ユーザーに毎日「今日は休養日」と入力させることは避けます。

### 他アクティビティ

筋トレ、ランニング、ストレッチ等の入力機能は将来的な任意機能とします。

初期版では必須にせず、入力負担を増やさないことを優先します。

## ランキング方針

最高グレードだけのランキングにはしません。初心者が参加しにくく、自己申告データとの相性も悪いためです。

候補：

- 今週の成長率
- 自己ベスト更新
- 継続セッション数
- 完登課題数
- Flash数
- 自分の過去平均との差

競技的なランキングと、自己成長を評価するランキングを分けます。

## MVP

初期版では機能を絞ります。

1. 登攀セッション作成
2. 課題のクイック入力
3. グレード・種目・完登・トライ数・Flash記録
4. 傾斜入力
5. Physical / Balance / Technicalの3軸入力
6. キャラクター1体の経験値・能力成長
7. 自動Rest Day / 回復
8. 日・週単位の簡単な履歴表示

最初からSNS、対戦、複雑な他スポーツ入力などを入れず、**「入力が楽しい／成長を見るのが楽しい／次に登りたくなる」**ことを検証します。

詳細仕様は `docs/product-spec.md` に整理します。
